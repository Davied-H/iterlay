# Iterlay 视频生成功能评审

评审日期：2026-11-26。结论：确认 7 项可优化问题，其中 3 项为功能逻辑缺陷；优先级为 4 项 P2、3 项 P3。本次只评审，未修改应用实现。

## 第一阶段：参考与引用

### 范围与方法

- 环境：当前 `http://127.0.0.1:5180/` 网页开发环境，桌面浏览器，现场截图视口 753×854；分支 main。
- 用户任务：选择模型、准备视频参考素材、设置参数、提交前确认、理解任务状态并处理异常。
- 实际操作：新建临时视频草稿，检查空状态、素材占位区、模型菜单、填写描述、打开并取消生成确认；两次核验模型菜单方向键行为和首帧占位区点击行为。临时草稿已移除。
- 源码核对：视频生成节点、生成控制器、全局任务恢复、视频 IPC、模型参数约束及结果节点。
- 隔离验证：使用内存中的虚拟任务和虚拟模型配置验证异常分支，不调用真实 Provider、不访问真实媒体、不提交计费请求。
- 未覆盖：真实视频质量、供应商响应速度、真实扣费、远端取消、真实下载失败和大画板播放性能。不能据此声称这些环节正常或异常。
- 项目 Hindsight 查询及知识页列表均因连接拒绝失败，未使用历史记忆作结论。

## 第三阶段：当前结论与建议

### 问题总览

| 编号 | 优先级 | 问题 | 用户损失 | 建议 |
|---|---|---|---|---|
| V01 | P2 | 查询异常被标成生成失败 | 用户可能在原任务仍运行时误点重新生成 | 区分提交失败、查询中断和远端失败 |
| V02 | P2 | 参考视频被当成源视频，阻断新建生成 | 添加有效参考后无法提交，默认还不显示原因 | 分开表示源视频与参考视频，统一展示禁用原因 |
| V03 | P2 | 素材占位区看起来可操作，实际没有添加入口 | 不熟悉连线的用户无法顺利开始图生视频 | 槽位支持选取、替换、移除，并保留连线 |
| V04 | P2 | 模型菜单方向键同时移动画布节点 | 选择模型会改动画板布局 | 隔离菜单键盘事件 |
| V05 | P3 | 模型选择偏配置列表，能力与参数变化不明确 | 用户需要记住技术 ID，反复试参数 | 友好名称、能力摘要、参数变化提示 |
| V06 | P3 | 费用确认缺少有用的费用信息 | 多一次确认，但仍不知道费用是否可估计 | 有价格时显示估算；未知时明确未知及计费方式 |
| V07 | P3 | 已可生成仍显示“等待输入”，长任务反馈不足 | 用户难判断就绪、继续等待或处理异常 | 状态与下一步一致，显示阶段与已等待时间 |

### V01｜查询异常被标成生成失败

- **问题事实与证据：** E6。控制器把提交、保存和后续查询放在同一个 try/catch 中；getVideoJob 的一次错误会将生成节点及结果占位标为 failed。见 [生成控制器](../src/features/generation/create-video-generation-controller.ts#L249)。
- **影响用户与用户价值：** 等待中的用户需要知道任务是否仍在服务商运行，避免把通信问题当成必须重新付费生成的问题。
- **业务价值与为什么现在改：** 减少误重试及费用争议。尚未观察到真实重复扣费，不能把风险写成已经发生的损失。
- **补充事实：** [全局恢复同步](../src/App.tsx#L1838)每约 2 秒查询任务列表，可能纠正误报；这不能保证用户在误报期间不会点击重试。
- **怎么改：** 已拿到任务 ID 后，查询异常进入“连接中断，正在恢复”；保留任务 ID 和结果占位，优先恢复查询。只有远端明确返回 failed 才提供“重新生成”。提交结果不明时也先核对原任务。
- **验收标准：** 已排队任务查询失败不变为终态；恢复时沿用原任务 ID，startVideoGeneration 仍只调用一次；真实远端失败仍能重新生成。
- **优先级理由：** P2，已有后台恢复替代路径，但误导用户对核心任务作判断。

### V02｜参考视频与源视频混为一谈

- **问题事实与证据：** E5。[视频节点](../src/components/canvas/VideoGenerationNode.tsx#L237)使用 sourceVideoPath 或任意 referenceVideos 判断“有源视频”；generate 模式随后返回“新建视频请使用新的生成节点”，并禁用提交。默认未开启高级模式时，阻断提示所在区域不会渲染，footer 也不展示这个原因。
- **影响用户与用户价值：** 使用多素材参考的用户需要能把视频作为运动或风格参考，而不是添加后突然不能生成。
- **业务价值与为什么现在改：** 修复一个现有输入端口对应流程的阻断，减少“模型支持但产品不可用”的情况。
- **怎么改：** 明确区分参考素材和改编/续写源视频；按模型能力决定参考视频是否可用。按钮禁用时始终显示最直接的原因及可执行的处理方式，不依赖高级模式是否展开。
- **验收标准：** 支持多参考且未超限的模型，添加参考视频后仍可新建生成；不支持时显示明确原因；改编与续写仍要求显式源视频。
- **优先级理由：** P2，特定核心分支无法完成；文生视频和图生视频路径仍可用。

### V03｜首尾帧槽位缺少直接操作

- **问题事实与证据：** E1。空的 [FrameSlot](../src/components/canvas/VideoGenerationNode.tsx#L595)仅渲染展示 DIV，首尾帧需要从画布连线输入；素材区没有“从画布选择”或本地选取入口，也没有明确的连线引导。已有图片时主要提供预览，替换和解除也不在槽位中完成。参考音频却有直接添加按钮。
- **影响用户与用户价值：** 新用户想直接选一张图片制作视频，需要先学习端口语义；熟练用户替换素材也要操作连线。
- **业务价值与为什么现在改：** 降低首次图生视频的启动成本，减少对口头说明与教程的依赖。
- **怎么改：** 将空槽位变成可点击、可键盘聚焦的入口，提供“从画布选择”和“上传”；保留连线方式；缩略图提供预览、替换、移除。不同角色对应不同说明，不把参考音频的独立入口孤立在外。
- **验收标准：** 不操作连线也能完成首帧添加、替换和移除；操作后角色与连线保持一致；Tab 可达且标签明确。
- **优先级理由：** P2，现有替代路径可用，但最直观的操作路径没有响应，影响首次发现与开始生成。

### V04｜模型菜单影响画布键盘操作

- **问题事实与证据：** E2。模型菜单及其子菜单仅阻止 pointerdown 传播，没有像时长/画幅 Select 一样处理 keydown。见 [模型菜单](../src/components/canvas/VideoGenerationNode.tsx#L708)。在当前页面复现两次。
- **影响用户与用户价值：** 使用键盘选择模型时，用户不应同时移动画布中已选节点。
- **业务价值与为什么现在改：** 防止参数操作引入意外布局修改，保持编辑器操作可信。
- **怎么改：** 菜单、子菜单及触发器隔离与画布冲突的键盘事件，同时保留菜单内部方向键、Enter 和 Escape 行为。
- **验收标准：** 菜单中的方向键操作不改变节点坐标和连接；退出菜单后，画布自身的方向键移动仍正常。
- **优先级理由：** P2，鼠标可作为替代，但键盘的正常操作会产生额外修改。

### V05｜模型选择与参数依赖不易理解

- **问题事实与证据：** E7。当前仅一个服务商和一个模型也要进入二级菜单，界面主名称为完整模型 ID，未展示适用输入能力摘要。[参数归一化](../src/components/canvas/VideoGenerationNode.tsx#L871)会替换新模型不支持的时长、比例、清晰度和声音选项，但缺少变更说明。
- **影响用户与用户价值：** 用户需要判断模型是否适合当前素材，并确认切换后输出规格是否改变。
- **业务价值与为什么现在改：** 减少试错与不符合预期的生成结果；这是布局重构中应一起解决的依赖关系。
- **怎么改：** 模型入口前置，显示易读名称和服务商，技术 ID 放到次级信息；能力显示“文生、首帧、首尾帧、多参考、声音”等明确支持状态，未知能力不伪装成支持；单选项减少层级。必要参数被调整时给出简短说明。
- **验收标准：** 选模型前能看到其适用输入；切换导致规格变化时可以明确知道哪项变化；只有一个模型时无须重复进入服务商子菜单确认。
- **优先级理由：** P3，当前能够选择，但判断和反复操作成本偏高。

### V06｜费用确认的信息价值不足

- **问题事实与证据：** E3。[控制器](../src/features/generation/create-video-generation-controller.ts#L93)中的 metadata 初始为空，当前确认费用统一回落到“由 Provider 计费”，即使其他位置存在部分模型价格展示，也未进入这里的确认摘要。弹窗同时展示不适用的 Iterlay 报价有效期说明。
- **影响用户与用户价值：** 用户需要在提交前理解能否估价、如何计费，以及确认的输出规格。
- **业务价值与为什么现在改：** 让确认真正支持决策，降低误解；不能在没有报价依据时编造费用。
- **怎么改：** 有可靠单价与计价条件时显示估算及来源；没有时明确“费用未知，由服务商结算”，提供计费信息入口。摘要包含模型、时长、清晰度、画幅和声音；不展示无关的内部报价术语。
- **验收标准：** 已知价格能随相关参数更新，未知价格不会显示成零或保证价格；取消不提交；确认摘要与实际输入一致。
- **优先级理由：** P3，确认与取消本身正常，但信息不足以支撑费用判断。

### V07｜状态说明与当前操作不一致

- **问题事实与证据：** E4。描述填写完成、按钮可用后，底部仍通过 [generationSummary](../src/components/canvas/VideoGenerationNode.tsx#L880)显示“等待输入”，因为该摘要只检查参考素材。任务中已有阶段标签和后台继续说明，但生成节点没有等待时长；Provider 的 progress 未在视频 IPC 的任务快照更新中传递到节点。
- **影响用户与用户价值：** 用户需要分清“可生成”“仍在排队”“生成中”“下载中”“查询中断”，而不是自行猜测下一步。
- **业务价值与为什么现在改：** 减少重复点击和对任务卡住的误判，配合 V01 形成完整异常处理。
- **怎么改：** 使用实际就绪条件驱动提示；等待中显示阶段、已用时间和最近一次更新。仅当供应商返回可信进度时展示百分比；继续明确区分“停止本地等待”和“取消远端任务”。
- **验收标准：** 只填有效描述即可显示可生成；排队、生成、下载、恢复和停止等待分别有对应文案；不伪造进度、成功率或预计完成时间。
- **优先级理由：** P3，任务流程本身仍有状态和恢复机制，但说明不够准确。

### 建议实施顺序

| 阶段 | 内容 | 可观察的完成标志 |
|---|---|---|
