# CLI 入口与使用引导方案

日期：2026-11-26。状态：已按确认的设计接入应用源码并完成网页验收；尚未重新打包或发布桌面 App。

## 目标与入口

在画板库左侧栏底部、回收站上方新增「CLI 与 Agent」，使用现有 Lucide Terminal 图标，行高、留白、文字及悬停反馈沿用底部工具项。侧栏收起后保留图标及同名 Tooltip。点击打开使用引导弹窗，关闭后焦点返回入口，不切换当前画板。

用户应能理解：可在终端直接使用，也可由 Coding Agent 调用；两者共享 App 的模型配置与画板；复制命令后应在哪里执行、在哪里检查结果。

## 弹窗构成

- 标题「用 CLI 和 Agent 创作」，说明「在终端或编程助手中生成图片、制作视频、管理画板，结果与 App 同步。」
- 桌面建议宽 760px，最大高度为窗口的 85%，窄窗口左右至少留 16px；固定标题区、正文内部滚动。沿用现有 Dialog、明暗主题、按钮与排版，不引入独立终端皮肤。
- 两个页签：「终端使用」和「Coding Agent」。首次默认终端，当前打开期间切换保留状态；每次重新打开刷新环境检测。
- 底部提供「完整使用指南」及「高级设置」文字入口。完整指南指向已有的中英文官网 Agent 指南；高级设置进入现有 Coding Agent 设置。

## 终端使用页

一屏按顺序显示三段，采用数字、标题和细分隔线，不做多层卡片或强制逐步翻页。

1. **确认环境**：检测 CLI 安装、PATH 与图片模型配置。CLI 缺失时显示「安装 CLI」，异常时显示具体原因及「检查与修复」；缺模型时提供「配置模型」。仅 CLI/PATH 有问题不妨碍阅读与复制帮助内容。模型标为「已配置」，不宣称远端服务可用。
2. **新开终端，检查连接**：展示 `iterlay status --json`，附独立「复制」按钮。补充「粘贴到终端运行；首次使用建议新开终端」。模型列表命令 `iterlay providers list --kind image --json` 放入可展开的检查说明。
3. **生成第一张图**：展示 `iterlay image generate --prompt "极简咖啡杯插画" --n 1 --out ./cup.png`，提供「复制生成命令」。命令下方说明「运行后使用已配置的默认图片模型生成 1 张，费用按模型服务计费」以及「文件保存到终端当前目录的 cup.png；画板保存到：实际默认画板名称」。不把复制操作描述成已执行或已生成。

结果说明提供「查看结果画板」按钮：默认画板已存在时打开它；自动模式尚无「CLI 创作」画板时显示「前往画板库」，不为浏览引导创建画板。末尾说明「日常使用无需先打开 App，CLI 可自动启动后台工作台」。

PATH 未配置时展示按实际平台及已安装路径正确转义的完整路径命令，并提供「修复命令路径」。不手工拼出带空格但未转义的命令。默认画板被删除时提示先重新选择，并链接到现有默认画板设置。

## Coding Agent 页

沿用现有检测、安装与 `using-iterlay` 引导。优先展示已检测到的 Agent；其他受支持 Agent 收入「其他 Agent」，名称必须按真实 id 映射，不把所有非 Codex 项都显示为 Claude Code。

1. 选择 Agent，显示「未安装 Skill」「Skill 已安装」等真实状态，提供按需安装或修复。
2. 提醒「安装后新开会话」，展示该 Agent 实际支持的 Skill 调用语法。
3. 默认提供「复制检查任务」，只检查连接与配置，不调用模型；「生成第一张图」作为第二项任务，先说明模型与费用并等待用户确认。复用现有任务文本与中英文版本。

Skill 已安装不等于会话已加载或已连接。导出 FIELD 示例素材及完整教学留在现有完整指南，避免首屏过长。

## 状态与交互

- 打开只读取本地状态，不自动安装、不发起模型请求。
- 检测时显示局部骨架；失败显示明确错误与「重新检测」，教程正文仍可阅读。
- 复制成功显示「已复制」约 2 秒；失败允许手动选择文本。
- 安装中仅锁定相关操作，完成后更新共享状态；失败原位重试。
- 配置模型时先关闭引导弹窗再进入现有设置，避免叠加弹窗；重新打开后刷新状态。
- 支持 Escape、关闭按钮、焦点约束及焦点归还；英文长文本、长安装路径在窄窗口内换行。

## 实施落点与验收

最小方案是新增侧栏按钮并直接打开已有 Coding Agent 设置。推荐独立引导弹窗，因为用户要求点击后弹窗说明用法，而且终端用户不需要先安装 Skill。

实施预计为一次小型前端改动：在 `LibraryShell.tsx` 的 `SidebarUtilityEntries` 加入口，新增 `CliGettingStartedDialog.tsx`，按需抽取 `CodingAgentSettings.tsx` 中的状态/安装逻辑供两处共用，复用 `AgentStarterGuide.tsx` 与现有 Dialog；新增文案接入现有 i18n。预期不超过 8 个应用文件，无新增命令、服务、凭据、数据迁移或自动启动终端功能。

主要风险是弹窗与设置页各自维护状态、命令或教学文案而产生差异；通过共用现有接口、任务文本及状态通知解决。前提是运行时包含现有 CLI 集成接口；旧运行时不具备接口时应给出更新说明，不显示伪造的检测成功状态。

实施验收覆盖：入口展开/收起、打开/关闭与焦点；CLI 缺失、PATH 异常、模型未配置、检测与安装失败；已就绪用户可直接复制；两种使用方式切换；默认画板存在/不存在/已删除；中英文及窄窗口；复制不触发生成。网页开发使用隔离工作区，不修改正式 CLI、Agent 配置或调用付费生成。完成后运行相关组件/行为测试、类型检查、i18n 检查与渲染层构建，并在真实网页检查布局和交互。

方案阶段依据仓库代码与 CLI 文档编写，尚未验证正式 App 的 CLI 安装或模型连接。方案阶段 Hindsight 连接失败，工作树已有其他任务改动；当时仅输出方案。后续实现可单独回退入口和弹窗，无需迁移用户数据。
