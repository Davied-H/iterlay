# Iterlay 项目记忆

## 2026-10-19 — 推广发布必须留档

- 用户要求在本项目持续记录每次对外发布，统一维护 `docs/marketing/publications.md`。执行推广或回答渠道覆盖问题前先读台账；发布、追加内容、排期、审核结果、移除和版本更新后及时更新，保留历史，不用准备稿或排期冒充已发布。
- 记录渠道与受众、永久链接、素材/版本、发布日期（不明则标注未知）、状态、核验日期及依据；阅读量和转化数据须附采集日期，不推算成用户数。后续推广先据此判断重复投放和渠道效果。

## 2026-10-15 — 默认在网页调试

**类型：** 偏好、流程
**标签：** browser-debugging, electron, verification
**适用场景：** 本仓库的日常开发、界面调试和功能验证。

- 默认运行 `pnpm dev`（别名 `pnpm dev:web`），在 `http://127.0.0.1:5180` 调试真实工作台。网页通过本地后台 Electron 服务调用同一套业务接口；隐藏服务进程属于网页模式的必要运行环境。
- 只有用户明确要求 App 测试时，才启动可见桌面应用或执行 Electron UI/E2E 功能测试，例如 `pnpm electron:dev`、`test:electron:*`。类型检查、单元测试、构建和打包检查可以正常执行。
- `pnpm dev:ui` 只用于独立组件的 `?preview=...` 预览，不用于判断真实生成、保存或导入导出是否正常。

## 2026-10-15 — 开发与正式数据隔离

**类型：** 禁忌、流程
**标签：** development-data, packaging, persistence
**适用场景：** 调整网页开发入口、后台桥接或验证流程。

- 网页模式使用 `tmp/browser-dev/user-data/`；可通过 `ITERLAY_BROWSER_DEV_USER_DATA` 指定其他开发目录。不要让网页测试连接已安装 App 的正式数据目录，也不要自动迁移正式数据到开发工作区。
- 网页桥接只能在未打包的开发模式下启用。正式 App 使用 Electron IPC；Vite 代理、浏览器调试通信及开发桥接模块应从生产产物排除。
- 浏览器是该开发工作区的唯一编辑端。保留单编辑会话约束、未保存离页提示、后台重启前保存确认，以及连接中断后的恢复。
- 退出或自动重启后台时，等待画板保存；保存失败应保留服务并提示重试，不能按超时直接强杀服务丢弃修改。

## 网页验证入口

- `pnpm test:browser:smoke` 连接已运行的网页服务；传入相同的 `ITERLAY_BROWSER_DEV_USER_DATA`。该验证使用本地离线模型响应，覆盖真实设置、画板读写、图片导入、生成、素材 HTTP Range、事件和会话独占。
- 修改自动保存、后台退出或重连逻辑时，运行 `pnpm test:browser:restart`，同样传入开发数据目录。它在真实浏览器中拖动图片并触发后台代码重启，验证保存确认、位置恢复、新会话和素材地址更新；测试结束会恢复编译文件并清理测试画板。
- 涉及启动模式或桥接改动时，额外验证生产前端构建不含开发通信代码，桌面包不含开发桥接模块；无需因此自动进行可见 App 功能测试。
